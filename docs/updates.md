# 预览版更新

点击主题按钮左侧的齿轮，选择“更新”。页面显示当前版本；“检查更新”从项目公开 Releases 获取版本信息。1.0 以前使用预览渠道，正式版只接收正式发布。

检查到新版本后，点击“更新并重启”。更新前保存词集，下载并校验 SHA-256；网络错误、校验失败、保存失败或授权取消时保留当前程序。Fedora 和 Debian 使用系统图形授权执行包管理器，Windows 与 Linux 单文件版在原进程退出后替换程序并重启。词集路径和保存位置保持不变。单文件必须放在当前用户可写目录。

0.9.3 及更早版本没有更新页，需要先安装一次带此功能的版本；之后可以在软件内更新。浏览器与开发源码预览提供版本检查，程序替换仅在桌面安装版、单文件版中启用。

## 发布约定

四个已通过测试的包与校验清单必须属于同一提交。将 Linux 单文件、Windows、RPM、DEB 放入 dist 后，执行 `build_tools/publish_release.py --commit COMMIT --notes-file NOTES`。脚本先创建草稿、上传全部包和清单，再发布为预览版。不要在发布后单独覆盖安装包；更改任何包时应发布新版本，避免校验清单失配。常规构建工作流只上传 Actions 产物，不会覆盖 Releases。

资料：[GitHub Releases API](https://docs.github.com/en/rest/releases/releases)、[polkit 图形授权](https://polkit.pages.freedesktop.org/polkit/pkexec.1.html)。

从 0.9.19 起仅发布带平台和安装方式的新文件名，不保留旧名兼容附件。0.9.18 及更早的更新器无法识别新文件名，需要手动安装一次。新版更新器优先选择新命名，仍可读取旧版历史发布信息；Red Hat 系通过 ID / ID_LIKE 识别，未知系统不会默认按 Fedora 处理。RPM 为单个不带 `.fcNN` 后缀的 noarch 包；运行依赖与发行版兼容性另行检查，RHEL 10 官方仓库缺少 WebKitGTK，当前尚不能直接支持。

## 后台检查与确认安装

联网启动后自动检查一次并缓存兼容更新，恢复联网可重试失败的启动检查。后台绝不调用 pkexec、包管理器或重启。缓存位于用户实际数据目录的 updates，记录已校验文件摘要并在下次启动时复用；出现更高版本时删除旧安装包缓存。设置按钮与更新标签右上角显示红点，悬停提示可更新版本及缓存状态，浏览设置不清除提示。安装仅在用户点击“更新并重启”后开始，成功后清除红点。

开发预览不自动下载；测试使用隔离目录和受控响应，不操作真实安装或提示词。0.9.24 包含启动目录与编辑会话恢复、保存失败时关闭及恢复副本、后台更新缓存、卸载工具等调整。发布必须使用同一提交上通过验证的各平台产物。

## 历史版本与卸载工具

发布成功后保留最新三个已发布版本及对应标签，再清理更早的发布和版本标签；草稿和非版本标签不会被清理。`build_tools/release_retention.py` 默认只预览计划，使用 `--apply` 才执行；发布工具只在完整新版本发布成功后调用清理。

新发布会附带 Windows、Linux 卸载工具及其校验值。Windows 安装包提供系统卸载项与开始菜单入口，RPM、DEB 提供 `prombee-uninstall` 和应用菜单入口。便携版卸载工具可移除旁边的新旧便携程序，均保留用户数据。详见 [卸载说明](UNINSTALL.md)。
